State your screens follow

Keep the app's state in the database and give each screen a live query. A write runs again every query that reads what it wrote, and the screen gets the new rows; nothing calls a redraw. It is for state that outlives a keystroke: keep a text box's typing in the component, and write when the user saves.

Running a query again is the query itself: a page of 50 open todos out of 1 000 to 3 000, ordered by an index, took 0.19 ms, and a write no live query reads costs about 2 µs. State in the page and live queries in Swift, Kotlin and Dart

Local and server, one flow

Open the database on the device as a replica of the rows it needs. Reads never wait for the network. A write shows at once and waits in a queue inside the same file until the server can be reached; then it is sent once, under its Idempotency-Key, and reaches every other screen that follows those rows. The server owns the data: a write it refuses is put back, and there is no CRDT and no merging.

The browser's sync and the native one in Swift, Kotlin and Dart are held to the same 58 scenarios: offline writes, retries, refusals, dropped streams, restarts. A server following your PostgreSQL hands a commit there to its subscribers 0.09 ms later at the median. Sync, sync on a phone and following PostgreSQL

Many writers, one file

One write runs at a time, and that costs little: a write holds the lock for microseconds, and its fsync runs after the lock is let go, so writers waiting on the disk share one. Readers take a shared lock and run beside them.

Traffic without a cache in front

The file is mapped into memory, and a read decodes the row straight from its bytes. There is no cache of fenecdb's own to warm, evict or keep in step with the database, so the server can take the reads you would have put a cache in front of.

Scale by tenant

Give each tenant a file of its own. Nodes hold the files, a router sends each request to its tenant's node, and each tenant has a copy that follows it on another node. With leases the router fails a node over by itself: the node stops writing before its tenants are promoted, so no tenant has two primaries. The limit is plain: one tenant lives whole on one machine.

Search by meaning, built in

A vector is a field like any other. Mark it @hnsw and near finds the nearest rows; mark a text @text and match ranks it by BM25; fuse puts the two rankings together. It is the same engine in a browser tab, on a phone and on the server, and in the page it is 241 KB of gzipped WebAssembly with no dependencies.

At a million 128-dim vectors, fenec-server over HTTP answers the nearest ten at 99.1% recall in 0.141 ms; PostgreSQL with pgvector, with the same index settings, at 98.6% in 2.076 ms. Method, and fenecdb beside PostgreSQL, SQLite and PGlite. The playground runs the same engine in this tab, with fenec studio over it.

Security

Every request passes the same checks, from the login to the disk.

  • Sign in safelyA token for the server, a read-only token for a dashboard. Repeated failures slow down.
  • Your sign-in providerTokens from Auth0, Clerk or Firebase work as they are. Keys rotate without a restart.
  • Each user, their own rowsEveryone sees only the rows they may; writing someone else's is refused.
  • A record of who did whatEvery refusal, schema change and admin action is written to a log.
  • Encrypted backupsBackups and archives are sealed with a key you hold, and so are copies kept in the browser.
  • Nothing borrowedNo third-party code in the engine or the server: nothing upstream to compromise.

    function query(string $q, array $params = []) {
    $ch = curl_init('http://127.0.0.1:8080/query');
    curl_setopt_array($ch, [
        CURLOPT_POST => true,
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_HTTPHEADER => ['Content-Type: application/json', 'Authorization: Bearer secret'],
        CURLOPT_POSTFIELDS => json_encode(['query' => $q, 'params' => $params]),
    ]);
    $body = json_decode(curl_exec($ch), true);
    $status = curl_getinfo($ch, CURLINFO_RESPONSE_CODE);
    if ($status >= 300) {
        throw new RuntimeException($body['error'], $status);
    }
    return $body;
}

    def query(q, params = [])
  req = Net::HTTP::Post.new(URI.join(URL, "/query"), "Content-Type" => "application/json")
  req["Authorization"] = "Bearer secret"
  req.body = JSON.generate(query: q, params: params)
  res = Net::HTTP.start(URL.host, URL.port) { |http| http.request(req) }
  body = JSON.parse(res.body)
  raise "#{res.code}: #{body["error"]}" unless res.is_a?(Net::HTTPSuccess)
  body
end
