Quickstart

Install fenecdb, make a collection, write two rows and query them. Pick a path: a browser tab, a server you reach from your language, or the shell. Each is a few commands, and shows what you should see.

The steps install release {{version}}, so what they print is what the release prints. The rest of these docs describe the repository's main, which can be ahead of it.

Try it now

Nothing to install: the Playground is the real engine running in this tab, with three collections to browse, a FenecQL editor with examples, and rows you can edit. Nothing you type leaves your browser.

In the browser

A database in the page. @fenecdb/web is the engine as WebAssembly and a dependency-free ES client. You need Node for npm and any static file server.

  1. Install it into an empty folder.

    npm install @fenecdb/web

  2. Save this as index.html beside node_modules. It opens a database, makes a collection, writes two rows and shows what two queries return: the rows from 2020 on, newest first, and a search for a word.

    <!doctype html>
<meta charset="utf-8">
<pre id="out">loading…</pre>
<script type="module">
import { Fenec } from './node_modules/@fenecdb/web/fenec.js';

const db = await Fenec.open('./node_modules/@fenecdb/web/fenec.wasm');

db.run('create collection notes (title text @text, year int @sorted)');
db.run('put notes {title: $1, year: $2}', ['Dunes', 2021]);
db.run('put notes {title: $1, year: $2}', ['Night at the oasis', 2024]);

const { rows } = db.run('get notes where year >= $1 order year desc', [2020]);
const hits = db.rows('get notes select title match title $1', ['oasis']);

document.querySelector('#out').textContent =
  JSON.stringify(rows) + '\n' + JSON.stringify(hits);
</script>

  3. Serve the folder over HTTP.

    python3 -m http.server 8000      # or: npx serve

  4. Open http://localhost:8000. The page shows both answers, as JSON.

    [{"id":2,"title":"Night at the oasis","year":2024},{"id":1,"title":"Dunes","year":2021}]
[{"title":"Night at the oasis","_score":0.62239116}]

It does not open over file://. A page opened from disk stays on loading…: the browser refuses module imports and WebAssembly.instantiateStreaming without an HTTP origin. Any static server works: python3 -m http.server, npx serve, nginx.

Bundlers, no npm, and Node

Serving node_modules as it is suits a first page. With a bundler you import @fenecdb/web and hand Fenec.open the module's URL, and a page whose queries run on a server imports @fenecdb/web/client and loads no module at all (Which package). No npm: the same files, the module and the collate/ data beside them, are fenec-web-v{{version}}.tar.gz on the release.

In Node, where fetch cannot resolve a relative path, hand Fenec.open the bytes:

import { readFile } from 'node:fs/promises';
import { Fenec } from '@fenecdb/web';

const wasm = await readFile(new URL(import.meta.resolve('@fenecdb/web/fenec.wasm')));
const db = await Fenec.open(wasm);

The database lives in the tab's memory until you keep it: persist writes it to IndexedDB, openFile to a file of the origin private file system, and db.live keeps a list on screen in step with the rows (Keeping a database, State in the page). A page can declare its collections in code instead, and the open makes them.

As a server

fenec-server is one process over one file, and every language reaches it over HTTP and JSON. Install it with Homebrew, the install script or a package, or start it from the Docker image or a release binary, then talk to it with curl and from your language.

  1. Start the server with a token. It runs in the foreground when it is not the image, so the next steps go in another terminal.

    docker run -d --name fenecdb -v fenecdata:/data \
  -p 127.0.0.1:8080:8080 -e FENEC_HTTP_TOKEN=secret \
  ghcr.io/fenecdb/fenec-server:{{version}}

    The image holds the server and nothing else; the data lives in the fenecdata volume. A container listens beyond localhost, so it asks for a token.

    brew install fenecdb/tap/fenecdb
    FENEC_HTTP_TOKEN=secret fenec-server --file data.fenec
    opened: data.fenec
fenec-server {{version}}: data.fenec  [sync=250 ms]
fenec-http {{version}} listening on: http://127.0.0.1:8080  [token]

    The formula installs fenec-server and fenec, the shell, on macOS and Linux (arm64 and x86_64): the release's own binaries, checked against their SHA-256, not built on your machine. brew upgrade fenecdb takes the next release.

    curl -fsSL https://fenecdb.com/install.sh | sh
    export PATH="$HOME/.fenecdb/bin:$PATH"   # the script prints this line
FENEC_HTTP_TOKEN=secret fenec-server --file data.fenec
    opened: data.fenec
fenec-server {{version}}: data.fenec  [sync=250 ms]
fenec-http {{version}} listening on: http://127.0.0.1:8080  [token]

    It puts fenec-server and fenec in ~/.fenecdb/bin (FENEC_INSTALL names another directory) with no sudo, and edits no shell file: it says how to put the directory on your PATH and leaves that to you. It downloads the latest release (FENEC_VERSION={{version}} names a release) from GitHub over https, with curl or a wget that checks certificates, and checks the tarball against the release's SHA256SUMS before it unpacks anything. That sum comes from the same release as the file, so it catches a damaged or cut-short download, not a release someone replaced. For macOS and Linux on arm64 and x86_64. To read it before it runs: curl -fsSL https://fenecdb.com/install.sh | less (install.sh).

    curl -fLO https://github.com/fenecdb/fenecdb/releases/download/v{{version}}/fenecdb_{{version}}-1_amd64.deb   # arm64 on an ARM machine
sudo apt install ./fenecdb_{{version}}-1_amd64.deb
    curl -fLO https://github.com/fenecdb/fenecdb/releases/download/v{{version}}/fenecdb-{{version}}-1.x86_64.rpm   # aarch64 on an ARM machine
sudo dnf install ./fenecdb-{{version}}-1.x86_64.rpm
    FENEC_HTTP_TOKEN=secret fenec-server --file data.fenec

    Each release carries a package for amd64 and one for arm64, with its checksum in SHA256SUMS; releases after 0.1.11 have them. They install fenec and fenec-server in /usr/bin and depend on nothing: the binaries are static.

tar -xzf fenec-v{{version}}-$TARGET.tar.gz
cd fenec-v{{version}}-$TARGET
    FENEC_HTTP_TOKEN=secret ./fenec-server --file data.fenec
    opened: data.fenec
fenec-server {{version}}: data.fenec  [sync=250 ms]
fenec-http {{version}} listening on: http://127.0.0.1:8080  [token]

    The folder holds fenec-server and fenec, the shell, and is the same download as the shell's below.

  2. Check it is up. The route needs no token.

    curl -s http://127.0.0.1:8080/_health
    {"ok":true}

  3. Make a collection and write two rows. The language is FenecQL, the values go as parameters, and secret is the token you started it with.

    curl -s http://127.0.0.1:8080/query -H 'Authorization: Bearer secret' \

curl -s http://127.0.0.1:8080/query -H 'Authorization: Bearer secret' \
  -d '{"query": "put notes {title: $1, year: $2}", "params": ["Dunes", 2021]}'
curl -s http://127.0.0.1:8080/query -H 'Authorization: Bearer secret' \

import (
	"context"
	"fmt"

	Title string `json:"title"`
	Year  int    `json:"year"`
}

func main() {

		log.Fatal(err)
	}

	hits, err := db.Query(ctx, "get notes select title match title $1", "oasis")
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(hits[0]["title"])
}

Other languages, and the REST routes

These are cut down from the programs on Your language, which also have the query builders, batches and typed errors. Run one twice and the third row is written twice, since a put without an id makes a row each time.

The REST routes read the same collection, and a stream sends the rows a filter holds, then each change to them (Subscriptions):

curl -s -H 'Authorization: Bearer secret' \
  'http://127.0.0.1:8080/notes?select=title,year&year=gte.2020&order=year.desc&limit=10'
curl -sN -H 'Authorization: Bearer secret' 'http://127.0.0.1:8080/notes/changes?year=gte.2020'

A release's files are listed with their checksums in SHA256SUMS:

curl -LO https://github.com/fenecdb/fenecdb/releases/download/v{{version}}/SHA256SUMS
shasum -a 256 -c --ignore-missing SHA256SUMS    # Linux: sha256sum -c --ignore-missing SHA256SUMS

There is no TLS in the server: on a network, put a terminator such as Caddy or nginx in front. fenec-server --ping is the health check for a container. Tokens, durability, limits and containers are on Server; every route is on HTTP reference. Past one machine, a read replica and archives are on Replication, a file per tenant behind a router, in one region or several, on Tenants and sharding, and the systemd units, alert rules and runbook to run them on machines of your own in Deploying it.

In the shell

fenec opens a database file and runs FenecQL on it, one statement at a time. It comes with every way of installing the server above, beside it: brew install fenecdb/tap/fenecdb, curl -fsSL https://fenecdb.com/install.sh | sh, the packages and the release tarball.

  1. Download the release and go into its folder. Skip this if you already have it from the server's steps, or installed it with Homebrew, the script or a package: then fenec is on your PATH (the script says how to put it there) and the steps below run fenec where they say ./fenec.

    TARGET=aarch64-apple-darwin   # or x86_64-apple-darwin, aarch64-unknown-linux-musl, x86_64-unknown-linux-musl
curl -LO https://github.com/fenecdb/fenecdb/releases/download/v{{version}}/fenec-v{{version}}-$TARGET.tar.gz
tar -xzf fenec-v{{version}}-$TARGET.tar.gz
cd fenec-v{{version}}-$TARGET

  2. Open a file of its own. Not the server's data.fenec: two processes over one file would corrupt it.

    ./fenec notes.fenec
    fenecdb {{version}} — notes.fenec
`.help` for help, `.quit` to exit

  3. At the prompt, make a collection, each field typed and the ones you filter, order and search by indexed, and write two rows. A write ends at a ;.

    fenec> create collection notes (title text @text, year int @sorted)
collection `notes` created
fenec> put notes {title: "Dunes", year: 2021};
1 records (16.04µs)
fenec> put notes {title: "Night at the oasis", year: 2024};
1 records (4.50µs)

  4. Read them back by a filter and an order, then search the words. The timings are yours.

    fenec> get notes where year >= 2020 order year desc
id  title               year
--  ------------------  ----
2   Night at the oasis  2024
1   Dunes               2021
(2 rows, 40.29µs)
fenec> get notes select title match title "oasis"
title               _score
------------------  ------
Night at the oasis  0.6224
(1 rows, 859.79µs)
fenec> .quit
Shell flags and multi-line statements 
./fenec notes.fenec                          # interactive
./fenec notes.fenec -c 'get notes limit 5'
echo 'get notes' | ./fenec notes.fenec
./fenec notes.fenec < seed.fenecql           # a script
./fenec --version                            # fenec <version>, and nothing opened

--version, or -V, prints the shell's version on stdout and exits 0 without opening the file; ./fenec version, with no dashes, opens a file named version, as any other word does. Releases up to 0.1.12 have no --version: the first line an interactive session prints names theirs.

Inside the shell: .help .tables .stats .functions .save <path> .checkpoint .quit.

A statement may run over several lines, and the shell runs it only once nothing after it can go on with it. Typed, a read or a schema change written on one line runs at Enter. A write, and a read written over several lines, wait for the next line: one that goes on with them — where, order, and — joins them, and an empty line or another statement runs them first. A ; after a statement runs it at once. So del notes with where id = 3 on the line under it deletes one row. A . command leaves a waiting statement waiting — .tables to look a name up before the where — and .quit leaves it unrun.

Piped from a file, a statement runs once the next one begins, and a paste is read the same way, its lines all there at once — a . command in either waits behind the statement before it, and runs once that has. -c reads its text whole, as POST /query does, so a text that does not parse runs nothing. A line that begins no statement — a where after a read that already ran at Enter, a wher mistyped, a clause written past a ; — is refused, and so is the statement before it, which it may have meant to go on with: del notes; where id = 3 deletes nothing.

A paste the terminal delivers in pieces further apart than 40 ms is read as typed lines, and a pasted statement whose last line has no newline yet waits for Enter like a typed one.

Releases up to 0.1.10 do not have these rules: they run every line whose brackets close, so there del notes deletes every row before a where under it is refused. Ending each write with a ;, as the session above does, behaves the same in both.

Fields and indexes can come later too, with no row rewritten: alter collection notes add field mood text, then create index on notes (mood) @hash over the rows already there (Changing a collection). Search finds words typed wrong and half typed with fuzzy and prefix (Typos and words begun), and highlight() and snippet() mark what matched (Highlights and snippets).
