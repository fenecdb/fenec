Serverless and Cloudflare

The browser module runs wherever V8 runs a WebAssembly module, a Cloudflare Worker among them. A Durable Object gives it what a file gives a server: one writer, and storage that outlives the process. So one object holds one database, as a tenant is one file on a fenec-pg node.

The second needs nothing new: Fenec.connect(url), the Python Client or any pg driver, and a function's connections are HTTP requests, so there is no pool to exhaust. The rest of this page is the first.

A database a Durable Object

import { DurableObject } from 'cloudflare:workers';
import { Fenec } from '@fenecdb/web';
import { checkpoint, persist, restore } from '@fenecdb/cloudflare';
import wasm from '@fenecdb/web/fenec.wasm';

export class Tenant extends DurableObject {
  async db() {
    if (!this.fenec) {
      this.fenec = await Fenec.open(wasm);        // the module as the Worker imports it
      await restore(this.fenec, this.ctx.storage);
    }
    return this.fenec;
  }

  async query(sql, params) {
    const db = await this.db();
    const out = db.run(sql, params);
    await persist(db, this.ctx.storage);          // kept before the answer goes
    await this.ctx.storage.setAlarm(Date.now() + 10_000);
    return out;
  }

  async alarm() {
    await checkpoint(await this.db(), this.ctx.storage);
  }
}

export default {
  async fetch(req, env) {
    const tenant = env.TENANT.get(env.TENANT.idFromName('acme'));
    const { sql, params } = await req.json();
    return Response.json(await tenant.query(sql, params));
  },
};

A Worker imports a .wasm file compiled, and cannot compile bytes at run time; Fenec.open takes the module so. integrations/cloudflare/example is this Worker with a tenant from the path, POST /t/<tenant>/query, and its test runs it under wrangler dev — workerd, as Cloudflare runs it — then stops and starts it over the same storage and reads the rows, a near's answer and each tenant's own database back.

What the storage holds

persist keeps what a file would hold: an image the first time, then only the writes since the last call — the engine's journal, as persist in the browser takes it for IndexedDB — until they outgrow half the image and a new image replaces them. Each is cut into pieces under a key-value backed object's 128 KiB a value; a SQLite-backed object takes 2 MB with the key, and {piece} can be set larger there. Every image goes under a generation of its own, and the record naming the whole one is written last, the generation before let go after it: storage that stops part way holds the last whole database. A Durable Object combines a call's puts into one atomic write besides; this does not lean on it, and a test stops the storage after every number of puts, an image's and an append's, and restores the last whole database each time.

A cold start

An object evicted, or a deploy, starts the next request with no database in memory: the module instantiated, the image and the writes after it read out of storage and loaded. The graphs the image holds are restored as they were; the writes after it are applied as the write path would, their vectors linked into the graph one after another — the browser module has one thread. So a checkpoint — a new image now, the writes since folded into it — once the writes stop, from an alarm, is what keeps a start short. The first near after a restart, against the ones after it, under wrangler dev on an M1 (make cloudflare-bench, median of five restarts; rows of a text, an int and a 128-dim vector, 1 000 a request, each kept before it was answered):

Limits

A Worker's isolate has 128 MB, the WebAssembly memory in it, and wrangler dev does not hold a Worker to it: the figures above reach past it. What the module holds, measured in Node on the same module (rows of a text, an int and a vector under HNSW):

A WebAssembly memory grows and never gives back, so an object that has written for a while holds what its lists grew to, and a checkpoint builds the whole image in it and copies it out. So an object holds about 20 000 rows of 128 dimensions or 3 000 of 768 with room to spare; past that, a fenec-pg node and Fenec.connect, or a tenant's data spread over more objects.
