Grafana

Grafana shows fenecdb two ways: the server's health through Prometheus, and the data itself — visitors, top pages, price candles — through the Infinity plugin, each panel one FenecQL statement. The repository's monitoring/ runs both dashboards with one docker compose up.

Run it

FENEC_HTTP_TOKEN=secret FENEC_METRICS_TOKEN=scrape \
FENEC_JWT_SECRET=$(openssl rand -hex 32) \
  docker compose -f monitoring/docker-compose.yml up -d
# the data:     http://127.0.0.1:3000/d/fenecdb-data
# the metrics:  http://127.0.0.1:3000/d/fenecdb

# down, the data and the token with it
docker compose -f monitoring/docker-compose.yml down -v
  • Seeded data. The first start writes thirty days of a product site's events, made by the traffic simulator of examples/analytics, and a week of trades in twenty invented symbols, 60 000 a day: about 108 000 events and 470 000 trades, written in two seconds.
  • Pinned versions: Grafana 13.2.2 and the Infinity plugin 4.1.1, installed before provisioning reads the data source that needs it.
  • No code in fenecdb. The data source speaks the HTTP endpoint every client speaks.
Details

The compose file starts fenec-server with a --policy, a one-shot seed container (Node, running monitoring/seed/seed.mjs with no install: Node strips the simulator's types as it imports it), Prometheus, and Grafana once the seed has finished. The seed makes events and ticks only where they are missing, so a restart keeps the data, and mints the token Grafana reads with each time it runs. GF_PLUGINS_PREINSTALL_SYNC installs the plugin before Grafana starts provisioning; the asynchronous GF_PLUGINS_PREINSTALL may still be downloading when the data source is read. The first start downloaded it in 14 s.

The JWT secret goes to the server as a file (--jwt-secret-file, from a compose secret) and not as FENEC_JWT_SECRET: the image's health probe, fenec-server --ping, runs in the same environment without the server's --policy, and with a secret and no policy it refuses to start, so the container stayed unhealthy. FENEC_PORT, GRAFANA_PORT and PROMETHEUS_PORT move the ports published on loopback.

Into a Grafana of your own, the same three pieces:

  1. The plugin: grafana cli plugins install yesoreyeram-infinity-datasource 4.1.1, or GF_PLUGINS_PREINSTALL_SYNC=yesoreyeram-infinity-datasource@4.1.1.
  2. A token for a role the policy lets read (below): fenec-server --jwt-secret-file jwt.secret --mint-token '{"sub":"grafana","role":"grafana","exp":1823000000}'.
  3. The data source: monitoring/grafana/provisioning/datasources/fenecdb.yml with your server's URL and the token, then the dashboard's JSON imported.
apiVersion: 1
datasources:
  - name: fenecdb data
    type: yesoreyeram-infinity-datasource
    uid: fenecdb-data
    url: http://fenecdb:8080
    jsonData:
      auth_method: bearerToken
      allowedHosts:
        - http://fenecdb:8080/query
    secureJsonData:
      bearerToken: $__file{/run/fenec/grafana.jwt}

A panel's query

Each panel posts a JSON body to /query: the FenecQL fixed in the dashboard, and Grafana's time range and interval as its parameters.

{
  "query": "get events select bucket(at, $3) as t, count(*) as events, count(distinct user) as visitors where at >= $1 and at < $2 group t order t",
  "params": [${__from}, ${__to}, $__interval_ms]
}
  • ${__from} and ${__to} are the panel's range in epoch milliseconds, which a timestamp field compares with as it is; $__interval_ms is the interval Grafana picks for the panel's width, which bucket takes as milliseconds.
  • In Infinity: type JSON, parser Backend, source URL, method POST, URL /query, body raw application/json, and a column for each item of the select list: timestamp for a time fenec-server answers as ISO text, number, string.
  • The answer is the rows, a JSON array, which the backend parser reads with no root selector.
The dashboard's statements

Every panel aggregates on the server, so Grafana is sent the points it draws and not the rows behind them. $1 and $2 are the range throughout; the recipes are Analytics and market data's.

-- Events, visitors and signups
get events select count(*) as events, count(distinct user) as visitors, sum(case when name = "signup_completed" then 1 else 0 end) as signups where at >= $1 and at < $2
-- Visitors over time: $3 is $__interval_ms
get events select bucket(at, $3) as t, count(*) as events, count(distinct user) as visitors where at >= $1 and at < $2 group t order t
-- Top pages
get events select path, count(*) as views, count(distinct user) as visitors where name = "pageview" and at >= $1 and at < $2 group path order views desc limit 10
-- Distinct users per day
get events select bucket(at, 1d) as day, count(distinct user) as users where at >= $1 and at < $2 group day order day
-- The symbol variable: its one column kept
get ticks select sym, count(*) as trades group sym order sym
-- Candles: $3 the symbol, $4 $__interval_ms
get ticks select bucket(at, $4) as t, first(px by at) as open, max(px) as high, min(px) as low, last(px by at) as close, sum(qty) as volume where sym = $3 and at >= $1 and at < $2 group t order t
-- Latest price per symbol
get ticks select sym, last(px by at) as price, (last(px by at) - first(px by at)) / first(px by at) * 100 as change, sum(qty) as volume where at >= $1 and at < $2 group sym order sym

Time and variables, passed safely

The statement never changes: what Grafana varies goes in params, and a value bound to $n is a value, never FenecQL. A text variable goes in as ${sym:doublequote}, with no quotes around it.

{
  "query": "get ticks select bucket(at, $4) as t, first(px by at) as open, max(px) as high, min(px) as low, last(px by at) as close, sum(qty) as volume where sym = $3 and at >= $1 and at < $2 group t order t",
  "params": [${__from}, ${__to}, ${sym:doublequote}, $__interval_ms]
}
  • Grafana writes variables into the body as text before it sends it; Infinity cannot bind them as JSON values. The range and the interval are numbers Grafana makes, so they are digits whatever a link says.
  • :doublequote puts quotes around the value and a backslash before each " in it. "${sym}" leaves a " in the value free to end the string, and ${sym:json} writes a single value as it is: Grafana 13 stringifies only a multi-value variable's list.
  • Keep a text variable the body's last string. The format leaves a backslash as it is, so a value holding \" does end its string; with nothing quoted after it, what follows can only make a body that is not JSON, which fenec-server refuses with 400 before it runs anything.
Details

A link carrying ?var-sym= sets the variable to anything, whatever the variable's query lists. Opened with a symbol written to close its string and send a statement of its own — S01"], "query": "get ticks select count(*) as n", "params": [" — the browser sent it as one escaped value, and the candles showed no data. Generated values through the format into the candles' body, 2.5 million of them, 1.2 million making valid JSON: none changed the body's shape. make grafana-check sends both kinds. The risk left is a symbol holding \", answered 400 rather than its rows.

The variable's escaping is about correctness more than about access. Any Grafana viewer can send a data source any query, through POST /api/ds/query, whatever its dashboards say, so the token is what decides what a Grafana user reads (below).

${__from} and ${__to} are written in twice: by Grafana's frontend, and again by the plugin's backend, which is what an alert rule has. $__interval_ms and dashboard variables are written by the frontend alone (Limits).

The read-only token

The data source reads with a JSON Web Token whose role the server's policy lets read two collections and write nothing.

# monitoring/policy.txt
events          read                   for grafana
ticks           read                   for grafana
  • It cannot write: a put, set or del is 403, and so is a schema change or /_changes. /_metrics and the statement counts take no JSON Web Token at all, and a collection the policy does not name does not exist for it.
  • It is a secret of the data source, encrypted in Grafana's database, sent as Authorization: Bearer, and in no dashboard JSON, query or inspector.
  • allowedHosts holds every query's URL to POST /query, host and path: through the data source, /_whoami is refused by the plugin.
Details

A rule's filter narrows the rows further — events read where site = $jwt.site for grafana — and is ANDed into every statement the token sends, so a Grafana per customer sees its own rows (Scoped access). The seed mints the token for a year, and Grafana reads it from a file when it starts ($__file{} in the provisioning). To rotate one, mint another, put it into the data source and restart Grafana; --jwt-max-age on the server bounds how far ahead any token's exp may lie.

Limits

  • Columns come back in the order of their names. The plugin's backend parser builds a frame's fields sorted by name, so each panel has Grafana's Organize fields transformation put them back in the select list's order.
  • Aggregate in FenecQL, not in Infinity. The plugin's own filters, summaries and computed columns run in Grafana over every row the answer holds; a get with no group sends its rows whole. group, bucket and limit on the server send the points a panel draws.
  • Alerting needs the backend parser, and a body that names its values. A rule runs its query in Grafana's backend, where nothing writes $__interval_ms or a dashboard variable: the candles' and the visitors' bodies, as the dashboard has them, were refused 400 as rules. With the interval written in, they evaluated, each number column a series of its own. Infinity's frontend parsers — Simple, UQL, GROQ — cannot alert at all.
  • A refresh runs every statement again. The plugin keeps no ETag, so the 304 that /query answers a client asking with If-None-Match while nothing it reads was written (Polling a read) is not used.

A plugin of its own

A dedicated fenecdb-datasource plugin is planned: FenecQL in the query editor, the time range and variables bound as JSON values rather than written into the body's text, columns in the select list's order and types from the answer, and alert rules over dashboard variables. Until then, Infinity reads the data with no code in fenecdb.

Checked end to end

make grafana-check starts monitoring/'s compose on ports of its own, asks Grafana's /api/ds/query for every panel's query and the variable's, as an anonymous viewer, and holds each frame to the same FenecQL sent to fenec-server directly, column by column. Then what the data source must refuse: a write, another path, and symbols written to close their string. CI runs it.
