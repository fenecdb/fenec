Your language

fenecdb speaks HTTP and JSON, so every language reaches it with the HTTP client it already has. No driver to install.

Every example on this page is a program that runs against a real server on each change to fenecdb (make languages-test). Official SDKs for these languages are coming in a later release (Phase 53); until then these few lines are the whole client.

Start a server

fenec-server --file app.fenec --http 127.0.0.1:8080 --http-token secret

Then pick your language. Each example makes a collection, writes two documents with a vector, asks for the nearest and handles a refusal. Each sends one FenecQL statement a request to POST /query, its values as $1, $2, ... in params, and the token as Authorization: Bearer.

Connect and search

pip install fenecdb   # the standard library alone
from fenecdb import Client, FenecError

db = Client("http://127.0.0.1:8080", token="secret")

db.query("create collection if not exists docs "
         "(title text, embed vector<3> @hnsw(cosine))")
db.query("put docs {title: $1, embed: $2}", ["Night at the oasis", [0.1, 0.2, 0.3]])
db.query("put docs {title: $1, embed: $2}", ["Dunes", [0.9, 0.1, 0.0]])

rows = db.query("get docs select title near embed $1 limit 5", [[0.1, 0.2, 0.3]])
# [{"title": "Night at the oasis", "_score": 0.99...}, {"title": "Dunes", ...}]

try:
    db.query("get nowhere")
except FenecError as e:
    print(e.status, e)   # 404 collection `nowhere`

AsyncClient does the same in an event loop; LangChain and LlamaIndex have stores of their own (Integrations).

async function query(q, params = []) {
  const res = await fetch('http://127.0.0.1:8080/query', {
    method: 'POST',
    headers: { 'content-type': 'application/json', authorization: 'Bearer secret' },
    body: JSON.stringify({ query: q, params }),
  });
  const body = await res.json();
  if (!res.ok) throw Object.assign(new Error(body.error), { status: res.status });
  return body;
}

In the browser there is no server at all: the same database runs in the page (JavaScript).

// query runs one FenecQL statement and decodes its answer into out.
func query(out any, q string, params ...any) error {
	body, _ := json.Marshal(map[string]any{"query": q, "params": params})
	req, _ := http.NewRequest("POST", "http://127.0.0.1:8080/query", bytes.NewReader(body))
	req.Header.Set("Content-Type", "application/json")
	req.Header.Set("Authorization", "Bearer secret")
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		return err
	}
	defer res.Body.Close()
	if res.StatusCode >= 300 {
		e := &FenecError{Status: res.StatusCode}
		json.NewDecoder(res.Body).Decode(e)
		return e
	}
	if out == nil {
		return nil
	}
	return json.NewDecoder(res.Body).Decode(out)
}

Or embed the engine in your process, with no server (Embedded Rust).

var http = new HttpClient { BaseAddress = new Uri("http://127.0.0.1:8080") };
http.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", "secret");

async Task<JsonElement> Query(string query, params object[] args)
{
    var json = JsonSerializer.Serialize(new { query, @params = args });
    var res = await http.PostAsync("/query", new StringContent(json, Encoding.UTF8, "application/json"));
    var body = await res.Content.ReadFromJsonAsync<JsonElement>();
    if (!res.IsSuccessStatusCode)
        throw new HttpRequestException(body.GetProperty("error").GetString(), null, res.StatusCode);
    return body;
}

await Query("create collection if not exists docs (title text, embed vector<3> @hnsw(cosine))");
await Query("put docs {title: $1, embed: $2}", "Night at the oasis", new[] { 0.1f, 0.2f, 0.3f });
await Query("put docs {title: $1, embed: $2}", "Dunes", new[] { 0.9f, 0.1f, 0.0f });

var rows = await Query("get docs select title near embed $1 limit 5", new[] { 0.1f, 0.2f, 0.3f });
var titles = rows.EnumerateArray().Select(r => r.GetProperty("title").GetString());

HttpClient and System.Text.Json, no package. The body is serialised whole: PostAsJsonAsync streams it chunked, and the server wants a Content-Length.

static final HttpClient HTTP = HttpClient.newHttpClient();

static HttpResponse<String> query(String json) throws Exception {
    var req = HttpRequest.newBuilder(URI.create("http://127.0.0.1:8080/query"))
        .header("Content-Type", "application/json")
        .header("Authorization", "Bearer secret")
        .POST(HttpRequest.BodyPublishers.ofString(json))
        .build();
    return HTTP.send(req, HttpResponse.BodyHandlers.ofString());
}

java.net.http alone, Java 11 and newer (text blocks need 15), run as java Search.java. The standard library has no JSON: the test reads the titles with a pattern, and a project reads the rows with Jackson or Gson.

function query(string $q, array $params = []) {
    $ch = curl_init('http://127.0.0.1:8080/query');
    curl_setopt_array($ch, [
        CURLOPT_POST => true,
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_HTTPHEADER => ['Content-Type: application/json', 'Authorization: Bearer secret'],
        CURLOPT_POSTFIELDS => json_encode(['query' => $q, 'params' => $params]),
    ]);
    $body = json_decode(curl_exec($ch), true);
    $status = curl_getinfo($ch, CURLINFO_RESPONSE_CODE);
    if ($status >= 300) {
        throw new RuntimeException($body['error'], $status);
    }
    return $body;
}

The curl extension and json_encode; Guzzle sends the same request.

require "json"
require "net/http"

URL = URI("http://127.0.0.1:8080")

def query(q, params = [])
  req = Net::HTTP::Post.new(URI.join(URL, "/query"), "Content-Type" => "application/json")
  req["Authorization"] = "Bearer secret"
  req.body = JSON.generate(query: q, params: params)
  res = Net::HTTP.start(URL.host, URL.port) { |http| http.request(req) }
  body = JSON.parse(res.body)
  raise "#{res.code}: #{body["error"]}" unless res.is_a?(Net::HTTPSuccess)
  body
end

Details: what the examples are held to

The programs under integrations/languages are the examples above with their asserts: make languages-test starts a fenec-server over a new file for each language and runs Python, Java, PHP and Ruby from their official images in Docker, and JavaScript, Go, C# and Rust with the toolchains on the machine. CI runs it on every change, so a change to the HTTP endpoint that would break one of them is caught before it ships.

Every answer is JSON: a read is an array of rows, a vector search's rows carry their _score, a write is {"affected": n}, and a refusal is a status of 400 and up with {"error": "..."} — 401 for a missing or wrong token, 404 for a collection that is not there, 409 for an id insert finds taken. A vector goes in as a JSON array of numbers and comes out as the shortest text that reads back as each f32. Values always go in params, never into the statement's text.

The server keeps a connection open between requests (HTTP/1.1 keep-alive) for a client that reuses it, as Go's, .NET's, Java's and ureq's do. A body is read by its Content-Length; a chunked one is refused.
