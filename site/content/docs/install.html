Install

fenecdb is two programs, fenec-server and the shell, fenec, and a package for each language that reaches the server. Pick the way that suits your machine.

The commands here install release {{version}}, so what they print is what that release prints. The rest of these docs describe the repository's main, which can be ahead of the release: a flag or a statement they show that your install lacks is in the next one, and fenec-server --help lists what yours has.

The install script

curl -fsSL https://fenecdb.com/install.sh | sh

It puts fenec-server and fenec in ~/.fenecdb/bin (FENEC_INSTALL names another directory) with no sudo, and edits no shell file: it prints the line that puts the directory on your PATH and leaves that to you.

export PATH="$HOME/.fenecdb/bin:$PATH"   # in ~/.zshrc, ~/.bashrc or ~/.profile to keep it
  • It downloads the latest release from GitHub over https, with curl or a wget that checks certificates; FENEC_VERSION={{version}} names a release.
  • It checks the tarball against the release's SHA256SUMS before it unpacks anything. That sum comes from the same release as the file, so it catches a damaged or cut-short download, not a release someone replaced.
  • Nothing runs until its last line. The script is functions, and main "$@" on its last line is what starts them, so a download cut short runs nothing. To read it before it runs: curl -fsSL https://fenecdb.com/install.sh | less (install.sh).
  • To remove it, delete ~/.fenecdb.

Homebrew

brew install fenecdb/tap/fenecdb

The formula installs fenec-server and fenec, the shell, on macOS and Linux (arm64 and x86_64): the release's own binaries, checked against their SHA-256, not built on your machine. brew upgrade fenecdb takes the next release and brew uninstall fenecdb removes it.

.deb and .rpm

Each release carries a package for amd64 and one for arm64, with its checksum in SHA256SUMS; releases from 0.1.12 on have them.

curl -fLO https://github.com/fenecdb/fenecdb/releases/download/v{{version}}/fenecdb_{{version}}-1_amd64.deb   # arm64 on an ARM machine
sudo apt install ./fenecdb_{{version}}-1_amd64.deb
curl -fLO https://github.com/fenecdb/fenecdb/releases/download/v{{version}}/fenecdb-{{version}}-1.x86_64.rpm   # aarch64 on an ARM machine
sudo dnf install ./fenecdb-{{version}}-1.x86_64.rpm

They install fenec and fenec-server in /usr/bin and depend on nothing: the binaries are static.

A release tarball

TARGET=aarch64-apple-darwin   # or x86_64-apple-darwin, aarch64-unknown-linux-musl, x86_64-unknown-linux-musl
curl -LO https://github.com/fenecdb/fenecdb/releases/download/v{{version}}/fenec-v{{version}}-$TARGET.tar.gz
tar -xzf fenec-v{{version}}-$TARGET.tar.gz
cd fenec-v{{version}}-$TARGET
./fenec-server --help

The folder holds fenec-server and fenec, and nothing needs installing: run them from there, or copy them where your PATH looks. The release page lists every file.

The Docker image

The image holds fenec-server and nothing else: no shell, no libc, under 3 MB. Its data lives in /data, which the command below keeps in a volume.

docker run -d --name fenecdb -v fenecdata:/data \
  -p 127.0.0.1:8080:8080 -e FENEC_HTTP_TOKEN=a-token \
  ghcr.io/fenecdb/fenec-server:{{version}}

A container listens beyond localhost, so the server asks for a token, or for --insecure where you publish the port to your own machine only, as the Quickstart does. Its command is --http 0.0.0.0:8080 --file /data/data.fenec --sync 250: write every flag out when you override it, or the file is dropped. Run it in a container has the rest: one instance a file, memory limits, Kubernetes.

From source

For a build the releases do not have, or to work on fenecdb: clone the repository and build with cargo and make. Build from source has the commands, the tests and what each make target does.

Checking a download

A release's files are listed with their checksums in SHA256SUMS:

curl -LO https://github.com/fenecdb/fenecdb/releases/download/v{{version}}/SHA256SUMS
shasum -a 256 -c --ignore-missing SHA256SUMS    # Linux: sha256sum -c --ignore-missing SHA256SUMS
